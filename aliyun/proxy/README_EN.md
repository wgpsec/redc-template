# Aliyun Multi-Node Proxy Scenario

## Scene Description

This scenario deploys multiple Shadowsocks-based proxy nodes on Aliyun, creates 10 spot ECS instances by default, and uses the redc plugin chain to generate a Clash configuration and a proxy-node bundle for PoJun Workers. It is suitable for quickly obtaining a batch of proxy exits that can be consumed together.

After deployment, you get the node public IP list, batch SSH commands, a locally generated Clash configuration file, and a self-contained `pojun-proxy/bundle.json` under the case directory. If R2 upload is configured, the Clash config can also be uploaded automatically to Cloudflare R2 for distribution.

## Prerequisites

- redc must already be configured with working Aliyun credentials.
- This scene only supports two regions: `cn-beijing` (Beijing) and `ap-northeast-1` (Tokyo).
- The scene uses spot instances by default, so node availability and final node count can be affected by market capacity.
- If you want automatic R2 upload, install and configure `rclone` first and prepare a Cloudflare R2 bucket.
- If R2 upload is not configured, the scene still works; you just need to use the locally generated Clash configuration file.

## Quick Start

```bash
redc pull aliyun/proxy
redc run aliyun/proxy
redc run aliyun/proxy -e node=20
redc status [uuid]
redc status [uuid] -o json | jq '.plugin_outputs'
redc stop [uuid]
```

The default deployment creates 10 nodes. To switch the region or override the generated config file name, you can also run:

```bash
redc run aliyun/proxy \
  -e region=ap-northeast-1 \
  -e node=10 \
  -e filename=team-aliyun.yaml
```

## Parameters

| Parameter | Required | Default | Example | Behavior Impact |
|-----------|----------|---------|---------|-----------------|
| `region` | No | `cn-beijing` | `ap-northeast-1` | Controls the deployment region. Only Beijing and Tokyo are supported, and each region maps to a different hard-coded instance type and availability zone. |
| `instance_name` | No | `proxy` | `team-proxy` | Controls the instance name prefix. |
| `node` | No | `10` | `20` | Controls how many proxy nodes are created. More nodes increase both cost and available exits. |
| `port` | No | `60001` | `60010` | Controls the Shadowsocks service port and affects the generated Clash configuration. |
| `password` | No | `O9E3b1/OdxCrLkTmWyTL7w==` | `StrongProxyPass123` | Controls the proxy authentication password and also affects the generated config file. |
| `filename` | No | `aliyun-config.yaml` | `team-aliyun.yaml` | Controls the generated Clash configuration file name locally or after upload. |
| `buckets_name` | No | `test` | `proxy-config` | Used only when R2 upload is enabled; defines the destination bucket name. |
| `buckets_path` | No | `/proxyfile/` | `/shared/aliyun/` | Used only when R2 upload is enabled; defines the upload path prefix. |
| `instance_password` | No | auto-generated | `YourPassword123!` | Controls the SSH login password shared by all nodes. If left empty, the template generates one automatically. |

## Outputs

- `public_ip` / `ecs_ip`: Public IP list of all proxy nodes, useful for checking whether the full node set is up.
- `ssh_commands`: Batch SSH commands for logging into each node and checking service status.
- `ssh_user`: Default SSH username, currently `root`.
- `ecs_password` / `ssh_password`: Shared SSH login password for all nodes.
- Clash configuration file: Generated by `redc-plugin-clash-config` from `port`, `password`, and `filename`; if R2 upload is configured, the upload plugin can distribute it further.
- `pojun-proxy/bundle.json`: A single self-contained file generated by `redc-plugin-pojun-proxy`; it records the stable pool ID, node count, source case, revision, and Shadowsocks nodes for the later PoJun Worker pool integration.
- `plugin_outputs`: A separate object in `redc status [uuid] -o json`, containing `pojun_proxy_bundle_file`, `pojun_proxy_pool_id`, `pojun_proxy_node_count`, and `pojun_proxy_revision`.

## FAQ

- If R2 upload is not configured, the scene still works. Use the locally generated Clash configuration file directly.
- If startup fails, check these items first:
	1. Whether the Aliyun API connection timed out.
	2. Whether the target region still has spot capacity.
	3. Whether the `rclone` configuration is correct.
	4. Whether the R2 bucket name or path settings are consistent.
	5. Whether the current account balance is sufficient for node creation.

## Notes

- The template uses hard-coded instance mappings per region: Beijing uses `ecs.n1.tiny` in `cn-beijing-f`, and Tokyo uses `ecs.t5-lc1m1.small` in `ap-northeast-1b`.
- `main.tf` enables `spot_strategy = "SpotWithPriceLimit"`, so stability and final node count can change with market price and capacity.
- The default security group opens all inbound TCP and UDP traffic. Tighten the exposure after deployment if the nodes are not meant to remain fully exposed.
- On macOS/Linux, the `pojun-proxy` directory is mode `0700` and `bundle.json` is mode `0600`; on Windows it inherits the current user's case-directory ACL. The bundle contains proxy passwords; do not upload it to public storage, commit it to Git, or paste it into logs.

## Appendix

- In the redc execution path, the Clash configuration is generated by `redc-plugin-clash-config`, and the R2 upload is handled by `redc-plugin-upload-r2`; the `upload_to_r2` function in `deploy.sh` is more relevant for standalone Terraform usage.
- If you want to enable R2 upload, install and configure `rclone` first:
	- https://github.com/rclone/rclone/releases
	- https://dash.cloudflare.com/ r2
